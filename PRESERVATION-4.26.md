# Проверка сохранности базы 4.25.0 при расширении до 4.26.0

Проверка 26 октября 2026 года не обнаружила удалённых исходных файлов,
ресурсов, рецептов, старых регистраций или параметров конфигурации из выпущенной
базы 4.25.0, содержащей предыдущие механики. Ресурсы оформления, игровые
данные и старые совместимости сохранены побайтово. Изменения существующего Java
кода ограничены семью файлами, перечисленными ниже; остальное расширение
добавлено отдельными классами и coremod-скриптами.

## Зафиксированная база и метод

Сравнение выполнено с самостоятельным архивом релиза
`dist/adaptation-wheel-1.20.1-4.25.0-sources.zip`, а не с изменяемым Git diff.
Архив не изменялся. Его SHA-256:

```text
FBADBA73C4375A8C7A8F18FF9532C3037FE3963954F3407F90F28EB79595D68A
```

Для каждого прежнего файла в `src/main/` и двух актуальных `embedded/` проверены
наличие и байтовое содержимое. Для JSON отдельно сравнены множества ключей и
значения прежних регистраций. Изменённые Java-файлы прочитаны в полном diff.
`NegativeEffects.java` и `AdaptationEvents.java` в безопасном конечном кандидате
полностью возвращены к прежним байтам 4.25.0. По открытым/защищённым
декларациям методов в семи изменённых файлах выполнено сравнение исходных
сигнатур: удалений не найдено.

Частный машинный отчёт находится вне исходников мода:
`<lab>/autonomous-compat-1.20.1/reverse/customstates426/preservation.json`.

## Рассмотренные изменения существующих файлов

| Файл относительно `src/main/java/ru/pasha/adaptationwheel/` | Фактическое изменение против архива 4.25.0 |
| --- | --- |
| `client/AdaptationScreen.java` | Одна строка: для изученной записи без каталога используется читаемое резервное имя из `DamageCategories`, вместо необработанного ID. Разметка и управление меню не переписаны. |
| `core/AdaptationAnalysis.java` | В конец evidence enum добавлен `DIRECT_HEALTH`; добавлена классификация доказанной прямой записи здоровья. Прежние enum ordinals не сдвинуты. |
| `core/AdaptationProfile.java` | Добавлены профили трёх новых состояний и резервный профиль нового health-write источника. Прежние ветви оставлены. |
| `server/CombatObserver.java` | Добавлен метод учёта фактической прямой потери здоровья до возможного лечения на завершении этапа. Прежние методы не удалены. |
| `server/DamageCategories.java` | Добавлены переводимые названия трёх новых native состояний. |
| `server/ModAttackCompatibility.java` | Прежний `directHealthWrite` сохранён и дополнен новым внутренним guard-контекстом; добавлены читаемые имена прямых источников и три записи каталога только при наличии соответствующих модов. Прежний каталог продолжает добавляться. |
| `server/SmartAttackAnalyzer.java` | Одна новая проверка добавляет evidence для новых health-write ключей; прежняя классификация других ключей не удалена. |

В существующих ресурсах изменены только три файла:

- `META-INF/coremods.json`: прежние 10 пар ключ/путь сохранены; добавлены
  `adaptationwheel_adaptive_states`, `adaptationwheel_autonomous_health`,
  `adaptationwheel_effect_dispatch`.
- `assets/adaptationwheel/lang/en_us.json` и `ru_ru.json`: только добавления
  названий, объяснения прямого здоровья и записи истории 4.26.0.

Добавленные production-файлы: `core/StatePlan.java`,
`server/AdaptiveStatePlans.java`, `server/AutonomousHealthGuard.java`,
`compat/adaptive-state-plans.json`, `coremods/adaptive_states.js`,
`coremods/autonomous_health.js`, `coremods/effect_dispatch.js`.
Документация, версия сборки и новые QA-фикстуры являются отдельными изменениями
релиза; они не заменяют перечисленные прежние игровые ресурсы.

Конечный `effect_dispatch.js` добавляет проверку в начало периодического метода
`MobEffectInstance`. Исходный виртуальный вызов `MobEffect.applyEffectTick`
внутри метода не заменяется и остаётся доступен обязательным mixin-перехватам
других модов. Прежняя попытка глобальной замены мгновенного dispatch удалена;
обычный мгновенный урон продолжает идти по родному пути Minecraft/Forge.
Это подтверждено чтением конечного скрипта; совместимость с конкретными
mixin-модами дополнительно требует отдельных native прогонов.

В рабочей папке исторически лежат и старые версии Boost, которые не входили
в архив 4.25.0. Это не новые зависимости 4.26.0: проверенный бинарный JAR
содержит только актуальные Boost 1.6.1 и DH 3.3.3.

Для каждой библиотеки совпали три хеша: копия в архиве исходников 4.25.0,
текущий файл `embedded/` и запись `META-INF/jarjar/` проверенного JAR 4.26.0.

```text
Distant Horizons 3.3.3 — 27700542 байта
A537A71171D935540B56B7598D0DE2C106F6F5026336C713D89A1D9EA0EA14E3
```

Дополнительно в проверенном бинарном JAR непосредственно сверены с прежним
архивом все 11 ресурсов assets вне языков, 12 файлов data и 4 старых compat
файла: каждый совпал.

Проверенный кандидат:
`artifacts/release-4.26.0/adaptation-wheel-1.20.1-4.26.0-trained.jar`.
Его SHA-256 на момент этой проверки:

```text
73DF99EFC76A2A9443931AB2D028D5F18C88EF8E8E3FC81BF595365737CA0B35
```

Если кандидат пересобран, этот хеш необходимо сопоставить заново; он не
подменяет итоговый `SHA256SUMS` релиза.

## Границы вывода

Это проверка сохранности конкретной выпущенной базы и смысла её изменений,
а не утверждение о побайтовом совпадении всего 4.26.0 с 4.25.0. Проверка
исходных деклараций методов не является полноценной проверкой бинарной ABI.
Новые глобальные перехватчики могут взаимодействовать с прежними модами даже
при неизменном старом скрипте; для этого нужны отдельные реальные игровые
регрессии и GameTest результаты в журнале валидации.

Эта проверка не запускала Gradle, не редактировала прежние исходники, JAR,
миры пользователя или конфигурации. Она не заявляет проверки всех 616 модов
в одной запущенной сборке и не заявляет, что произвольные неизвестные
capability-поля можно безопасно нейтрализовать.
