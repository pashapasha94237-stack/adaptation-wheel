# Проверка релиза 4.33.0 — облик колеса

Дата: 29 октября 2026. Minecraft Java 1.20.1, Forge 47.4 / Java 17.
Основа — 4.32.0; Adapt Boost 1.7.0 и Distant Horizons 3.3.3 встроены побайтово прежними.
**4.33.0 заменяет 4.32.0**: тот же mod ID, ставится один файл вместо прежнего колеса.

Экран сделан по дизайну `wheel-skins-menu` (ревизия 1, утверждён в AdaptationHub 29 октября 2026): экраны
`screen-1.png` (широкий), `screen-2.png` (компактный), `screen-3.png` (кнопка в меню J) и `mock.html`. Модели обликов —
утверждённые m5, m6, m9, m10, m13, m14 из дизайна `wheel-models-2026-10-29`.

## Что добавлено

- Экран «Облик колеса» (`client/WheelSkinScreen`, раскладка — чистый класс `client/SkinLayout`): список семи
  обликов с живыми миниатюрами, предпросмотр персонажа с выбранным колесом (медленное вращение, поворот мышью,
  «▶ Щелчок этапа» — поворот на 45° за 0,35 с и пульс 18 тиков, как после этапа), описание, «Надеть»/«Надет».
  Открывается кнопкой «Облик» в меню J (слева от «Обучения», с подсказкой) и Ctrl+K в меню. Клавиши: ↑↓, Enter,
  Esc/Backspace (и клавиша меню). Компактная раскладка — при ширине GUI меньше 560 или высоте меньше 356.
- Облики (`core/WheelSkin`): `classic` (прежняя модель `WheelModel` и `wheel.png`, без изменений) и шесть моделей из
  коробок: `clockwork`, `ice_crown`, `armillary`, `event_horizon`, `ouroboros`, `storm_ring`. Файлы моделей
  AdaptationHub лежат как есть в `wheel_skins/*.json`; `core/SkinRig` — перенос правил программы (группы, поворот,
  покачивание, текстуры граней, упакованные в атлас `DynamicTexture`). Светящиеся материалы рисуются вторым
  проходом с полной яркостью (`beaconBeam`), остальное — `entityCutoutNoCull` с освещением мира.
- `client/SkinRenderer` рисует облик и на голове (`WheelRenderLayer`), и в интерфейсе (миниатюры и предпросмотр с
  настоящим игроком через `EntityRenderDispatcher`, после каждого рисунка очищается глубина в пределах scissor).
- Настройка клиента `adaptationwheel-appearance-client.toml`, ключ `wheelSkin` (`CLASSIC` по умолчанию).
  Собственная запись идёт через `ConfigWatch.ownSave`, поэтому адаптация «Правка конфига» на неё не реагирует.
- Сеть: `PROTOCOL` `"17"` → `"18"`, пакет 6 (клиент → сервер, id облика, до 64 символов) и пакет 7 (сервер →
  клиент, id сущности и облик). Сервер хранит облик по UUID, рассылает его всем, кто видит игрока, а новому
  наблюдателю — при начале слежения (`sendTo`, кроме самого игрока; классический облик тоже, чтобы стереть
  прежний под тем же id сущности). При выходе облик забывается. Клиент шлёт выбор при входе, при «Надеть» и
  при перезагрузке настройки (правка файла или Configured).
- Configured 2.2.3: строка «Облик колеса» в его экране настроек открывает `ChangeEnumScreen`; событие открытия
  экрана заменяет его на «Облик колеса», а «Надеть» вызывает и собственное сохранение Configured
  (`integration/ConfiguredSkinAccess` читает его поля через отражение; если поля не найдены — остаётся экран
  Configured и пишется предупреждение).
- Тексты: `skin.adaptationwheel.*` (экран, названия, подписи, описания), `config.adaptationwheel.wheel_skin`,
  `meta.adaptationwheel.changelog.4.33.0` в `ru_ru.json` и `en_us.json`; к игроку на «ты», без слов, указывающих пол.

## Модульные тесты (`coreTest`, входят в `check` каждого варианта)

- `SkinRigTest`: id обликов стабильны, неизвестный id даёт классический облик; перенос арифметики JavaScript
  (FNV-1a, `Uint8ClampedArray`, `toFixed(2)`, порядок матриц); у каждой из шести моделей 20–1000 коробок, атлас —
  степень двойки до 1024, текстуры скопированы без наложений и непрозрачны, шум текстур детерминирован, высоты в
  пределах над головой и ни одна коробка (с учётом покачивания) не входит в голову со шляпным слоем.
  Итог: 6 обликов, 668 коробок.
- `SkinLayoutTest`: размеры Паши (1146×472 — широкий, 462×265 — компактный, превью 280×183) и сетка 320…1920 ×
  240…1080 — 17 633 размера GUI; карточки, превью, кнопки и строка статуса внутри панели и не накладываются.

## GameTests

171/171 (169 прежних + 2 новых в `SkinGameTests`): облик доходит до каждого видящего игрока в формате пакета 7
(читается из настоящих байтов канала), классический облик тоже отправляется, самому игроку — нет; облик
переживает возрождение (новый `ServerPlayer` с тем же профилем) и забывается при выходе. Пакеты ловятся на уровне
`Connection`: `PacketDistributor.PLAYER` Forge пишет прямо в соединение, мимо слушателя пакетов.

## Настоящий клиент

Пробный мод `Skins433Qa` (`...\multi-mod-compat-1.20.1\probe`, группы `skins433-wide.json`,
`skins433-compact.json`, `skins433-optifine.json`), jar `adaptation-wheel-1.20.1-4.33.0-trained.jar`. Клиент
запускается из копии файлов игры `...\multi-mod-compat-1.20.1\mc-runtime` (скрипт `copy-runtime.ps1` копирует из
`.minecraft` версию `Forge 1.20.1`, её библиотеки, файлы установщика Forge и ресурсы; сама `.minecraft` только
читается), с отдельными папкой игры и `%APPDATA%`.

Шаги: свежий клиент носит классический облик; меню J открыто, кнопка «Облик» слева от «Обучения» на той же строке,
у неё есть подсказка; Ctrl+K открывает «Облик колеса»; раскладка компактная ровно в окне лаунчера; выбран
надетый облик; 4 × ↓ выбирают «Горизонт событий», ↑↓ не уводят фокус на кнопки, выбор не надевает; Enter надевает,
кнопка становится неактивной «Надет»; сервер получил облик; «Щелчок этапа» целит ровно на 45°; нажатие и
протаскивание в превью поворачивает его и останавливает вращение; снимок каждого из семи обликов в меню; все
шесть моделей загрузились; Enter надевает «Уробороса»; Esc возвращает в меню J; вид от третьего лица спереди — снимок
каждого облика на игроке в мире, сервер следует за каждой сменой; возврат к классическому облику дошёл до сервера,
файл настройки содержит `wheelSkin = "CLASSIC"`. С Configured: его собственный `ChangeEnumScreen` для «Облика
колеса» заменён экраном облика, «Надеть» меняет облик и передаёт значение в сохранение Configured, Esc
возвращает на экран Configured.

## Честные границы

- Два живых клиента рядом не запускались: рассылка облика другим игрокам проверена GameTest-ом по байтам пакета,
  а отрисовка чужого облика — тем же кодом, что и своего (`WheelSkinClient.of`).
- Шейдеры OptiFine, выделенный сервер и Configured, открытый мышью через список модов (в проверке экран
  Configured создаётся его же конструктором), не проверялись.
- Сервер 4.32 и клиент 4.33 (или наоборот) не соединятся: версия протокола выросла.
