# Две версии анализатора (с 4.15.0)

Устанавливается **только один** из файлов; у них один и тот же mod ID. Сейчас это
`adaptation-wheel-1.20.1-<версия>-trained.jar` / `-untrained.jar` (без интернета) и
`-trained-online.jar` / `-untrained-online.jar` (с советником); в 4.15.0 они назывались `-offline` и `-online`:

- без интернета (`trained` / `untrained`): улучшенный локальный анализатор,
  без нейросети и без обращений анализатора к интернету. API-конфигурация не
  регистрируется; сетевой режим дополнительно заблокирован ресурсом сборки.
- с интернетом (`trained-online` / `untrained-online`): тот же локальный анализатор плюс
  экспериментальный советник через внешний нейросетевой API. При отключении,
  ошибке или отсутствии настройки работает локальная система.

Обе версии содержат колесо, меч, прежние интеграции, встроенную оптимизацию и
восемь механик из UTILITY-MECHANICS.md. Прогресс общий по формату; API-ключи и
ответы с секретами в сохранение игрока не записываются. Локальный анализатор
не называется нейросетью: в автономном JAR нет весов языковой модели.

## Что улучшено в обеих версиях

Учитываются совместно владелец, прямой источник/снаряд, тип урона, полоса
дистанции, негативные эффекты и наблюдаемое состояние босса. Изменение расстояния
не сбрасывает накопленную защиту и не создаёт запись для каждого экземпляра.
Неизвестные снаряды по-прежнему разделяются по зарегистрированному типу. Для
модового владельца с непрозрачным общим `generic/magic/indirect_magic` создаётся
отдельный ключ `attack:<mod>:observed/<owner>/damage/<namespace>/<type>`:
общая адаптация к `generic` не открывает эту способность автоматически.
Ранее точно определённые техники Jujutsucraft сохраняют приоритет перед этим
резервным ключом; изученная техника не заменяется общим новым распознаванием.

Подготовка к выстрелу, появление снаряда, попадание, взрыв и отрицательный эффект
собираются в цепочку **по конкретному владельцу**, с ограничением разрыва между
событиями. Следующее событие предлагается только после как минимум трёх
повторений и согласия не менее 80% наблюдений. Предупреждение не означает
гарантированный будущий ход босса и не управляет персонажем.

Запоминаются устойчивые интервалы атак, штатные фазы Дракона Края и защищённое
состояние Иссушителя. Для произвольного босса без доступного описания фаз
используются диапазоны здоровья; меню честно называет их диапазонами, а не
выдумывает название способности. Атрибутированный дебафф в течение пяти тиков
после удара может уточнить слабую догадку о категории. Явные registry-теги
имеют приоритет; положительные эффекты не изучаются.

Перед лечением от завершённого этапа сравниваются ожидаемая полная защита и
фактическое здоровье/поглощение. При однозначном защищённом контакте считаются
проверки без потерь и возможные обходы. Смешанные защищённые и незащищённые
попадания в одном окне не объявляются доказанным обходом. При обнаружении
потери меню показывает её величину. Анализатор **не объявляет такой обход
исправленным** и не откатывает произвольные изменения здоровья чужих модов.

Объём подробных наблюдений с 4.42 не ограничен: старые адаптации, варианты,
последовательности и контексты переходов не вытесняются новыми. Статистика и
переходы сохраняются в NBT.

## Настройка интернет-версии

Нейросеть и платный аккаунт не входят в JAR. Нужен выбранный владельцем сервис
с совместимым методом Chat Completions. Реальная модель этим выпуском не
выбирается и не скачивается. Работоспособность и стоимость конкретного сервиса
зависят от его настроек и вашего доступа.

1. Запустите online-версию один раз. Откройте её параметры через Configured
   или `config/adaptationwheel-neural-common.toml`.
2. В `endpoint` укажите полный HTTPS-адрес метода `/v1/chat/completions`.
   Адрес по умолчанию пустой. HTTP разрешён только на loopback для локального
   сервиса/тестирования; перенаправления и адрес с ключом в URL не принимаются.
3. В `model` укажите модель, доступную на этом сервисе.
4. Создайте переменную окружения `ADAPTATION_WHEEL_API_KEY` со своим ключом
   и перезапустите лаунчер/сервер, чтобы он получил переменную. В
   `apiKeyEnvironment` вводится **имя переменной**, а не ключ. На выделенном
   сервере ключ нужен серверному процессу. Секрет не синхронизируется клиентам.
5. Установите `enabled=true`. Для сервиса без поддержки JSON Schema можно
   отключить `strictJsonSchema`, если он поддерживает JSON-object mode.
   Локальная проверка ответа остаётся строгой.

По умолчанию: максимум 12 запросов в час на серверный сеанс, не чаще одного
в минуту, повтор того же набора признаков — не раньше чем через пять минут,
тайм-аут 8 секунд. Запросы выполняются в отдельном ограниченном потоке.
На смену текущего таймера ждать нейросеть не нужно: обычная адаптация продолжается.

Отправляются только ID игровых источников, категории, дистанционная полоса,
эффекты, наблюдаемая цепочка и числовая оценка опасности. Имена/UUID игроков,
чат, координаты, территория, файлы и содержимое инвентаря не отправляются.
Сервис получает эти игровые признаки в соответствии со своей политикой.

Ответ — только категория, ограниченное время первого этапа/приращение и оценка
уверенности. Он не содержит команд, степени защиты, урона или права менять мир.
Совет рассматривается только для слабой локальной классификации; подтверждённые
штатные данные выигрывают. Уже начатый этап и его накопленная работа сохраняются.
Ручные параметры времени в Configured имеют прежний приоритет. Невалидный ответ,
HTTP-ошибка, тайм-аут и отсутствие ключа не отключают локальную защиту.

Формат адаптера сверялся с [официальным описанием Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)
и [структурированного JSON-вывода](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=chat).
Совместимость произвольного стороннего API не гарантируется.

## Что действительно проверено

Обе реальные разновидности JAR запускались в отдельных мирах Minecraft.
Проверены работающая защита новой способности, реальные боевые события,
переоценка категории без сброса таймера, повтор цепочки, измеренный обход,
сохранение/пакеты/меню. Сетевой путь проверен на **локальном HTTP-макете**:
совет попадает в серверную классификацию, ошибка возвращает резервную логику,
автономная разновидность не делает запросов. Проверены тайм-аут, oversized-ответ,
невалидные данные, HTTP429 и запрет перенаправления.

Внешняя коммерческая нейросеть без предоставленного пользователем доступа не
вызывалась. Качество рассуждений конкретной модели не проверено и «идеальный
интеллект» не заявляется. Особый код чужого мода, стирающий причину воздействия
или меняющий здоровье/состояние вне известных событий, всё ещё может потребовать
специальной интеграции. Новая строка в каталоге сама по себе не доказывает защиты.
