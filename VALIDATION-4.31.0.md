# Проверка релиза 4.31.0 — команды /adaptation

Дата: 28 октября 2026. Minecraft Java 1.20.1, Forge 47.4 / Java 17.
Основа — 4.30.0; Adapt Boost 1.7.0 и Distant Horizons 3.3.3 встроены побайтово прежними.
**4.31.0 заменяет 4.30.0**: тот же mod ID, ставится один файл вместо прежнего колеса.

## Что добавлено

Команды для мода, все четыре группы, которые выбрал Паша. Прежние `/adaptation`, `menu`, `on`, `off`, `reset`,
`status` работают как раньше.

| Команда | Кто | Что делает |
|---|---|---|
| `/adaptation list [страница]` | любой игрок | свои адаптации по 10 на страницу, сначала высокие этапы; у строки ключ при наведении, клик подставляет `info` |
| `/adaptation info <адаптация>` | любой игрок | название, ключ, свой этап и что дают этапы: подсказка бытовой адаптации, защита по этапам, укорочение эффекта, свет для темноты, текст Бесконечности |
| `/adaptation enable/disable <адаптация>` | любой игрок | тот же переключатель, что в меню J; выключить можно и ещё не начавшуюся адаптацию |
| `/adaptation learn <игроки> <0–4> <адаптация>` | оператор | выставить этап для проверки |
| `/adaptation forget <игроки> <адаптация>` | оператор | забыть одну адаптацию |
| `on`, `off`, `reset <игроки>`, `status <игрок>`, `list <игрок> [страница]` | оператор | то же для других игроков |

Оператор — уровень 2, как для `/give`; в одиночной игре это владелец мира с читами.

## Как устроено

- Адаптация — последний аргумент, строка до конца команды. Её можно назвать полным ключом или последней частью
  ключа. Порядок поиска: точный ключ, затем ключ после `DamageCategories.canonicalKey` (как у самого урона), затем
  единственный ключ, который кончается на `:<часть>`. Если подходят несколько, команда перечисляет их и просит
  уточнить (например, `wither` — это и босс, и эффект).
- Подсказки Tab сервер считает сам: сначала свои адаптации игрока, затем весь каталог (как в меню J). Слово
  ищется в начале ключа и после `:` или `_`. Подсказок не больше 200, свои адаптации в этот предел попадают первыми.
- `learn` вызывает `AdaptationState.setStage`. Повышение работает как пройденный этап (`AdaptationEvents.stageGiven`):
  сообщение, звук, поворот колеса, укорочение идущего вредного эффекта. Лечения нет. Понижение тихое, колесо не
  поворачивается. Этап V (существование) командой не выдаётся.
- `disable` для адаптации, которой ещё нет, создаёт выключенную запись, и тогда адаптация не начнётся (как
  переключатель в меню J).
- Оператор, изменивший чужое колесо, видит итог с именем игрока, а для нескольких игроков — одну строку с их
  числом; сам игрок видит своё сообщение.
- Ошибки (нет такой адаптации, несколько подходящих, ни у кого из указанных её нет) приходят красной строкой, и
  команда ничего не меняет.

## Тесты

- **GameTests: 156 из 156.** Новые — 9 тестов в `CommandGameTests`. Команды выполняются настоящим диспетчером
  сервера, а сообщения читаются из пакетов чата, которые получил игрок:
  - `learnSetsStageByFullKeyOrShortName` — этап по полному ключу и по короткому имени (и у бытовой адаптации),
    этап сохраняется; повышение объявляется и поворачивает колесо, понижение тихое; полный ключ кадавра ведёт
    к адаптации зомби; этап 5 не принимается;
  - `forgetRemovesOneAdaptation` — забывается одна адаптация, остальные на месте; если её ни у кого нет — ошибка;
  - `unknownAndAmbiguousNamesFail` — неизвестное имя и `wither` (босс и эффект) дают ошибку и ничего не меняют;
  - `onlyOperatorsSetStagesOrTouchOthers` — игрок без прав не видит `learn`/`forget` и чужих игроков в дереве
    команд и не может выполнить их даже по имени; консоль может;
  - `disableStopsEvenAnUnstartedAdaptation` — выключенная заранее адаптация не начинается от удара; выключенная
    не растёт и не защищает даже на IV этапе; после `enable` снова защищает;
  - `listPagesAndInfo` — 12 адаптаций на двух страницах, страница за концом показывает последнюю; `info` для
    бытовой адаптации, существа, эффекта, холода и темноты;
  - `operatorsManageOtherPlayers` — `learn`, `off`, `on`, `status`, `list`, `reset`, `forget` для другого игрока
    и для `@a`, каждый слышит своё, оператор — одну строку;
  - `suggestionsOfferKeysWithNames` — «zom» даёт зомби с переведённым названием, слово ищется и после `_`, свои
    адаптации первыми, консоль подсказок не получает;
  - `givenStageShortensARunningEffect` — повышение командой укорачивает уже идущий вредный эффект, как
    пройденный этап.
- **Проверка самих тестов.** В код по одной вносились восемь намеренных поломок, после каждой — полный прогон
  GameTests, затем файл восстанавливался (сверен по хешу):

  | Поломка | Что поймало |
  |---|---|
  | `learn` без прав оператора | `onlyOperatorsSetStagesOrTouchOthers`: «A player without permission set a stage» |
  | `on`/`off`/`reset` для других без прав | тот же тест: «A player without permission reset another» |
  | из нескольких подходящих брать первую | `unknownAndAmbiguousNamesFail`: `wither` не дал ошибки |
  | нет коротких имён | 7 тестов |
  | повышение без `stageGiven` | 3 теста, среди них `givenStageShortensARunningEffect` |
  | `disable` только для уже начатой адаптации | `disableStopsEvenAnUnstartedAdaptation` |
  | понижение тоже поворачивает колесо | `learnSetsStageByFullKeyOrShortName` |
  | свои подсказки в конце списка | GameTests не ловят: в мире GameTest каталог меньше 200; проверено в игре |

  Первый прогон нашёл два слабых теста. «`learn` без прав» ловила только проверка дерева команд: тест вызывал
  `@s`, а селектор и сам требует прав. Теперь игрок вызывает команду по имени. «Повышение без `stageGiven`» тест
  эффекта пропускал: новый эффект и так помечается к укорочению при появлении. Теперь эта метка сначала
  проходит на этапе 0. После правки обе поломки ловятся.

## Настоящая игра

Пробный мод `Cmd431Qa` (группы `cmd431*.json`). Каждый прогон идёт в своей папке: свой мир, свои настройки,
свой `%APPDATA%`; файлы набора только копировались. Мир одиночный, с читами, поэтому владелец — оператор.
Команды набираются настоящим клиентом (`sendCommand`), как из чата. Каждый шаг проверяется на сервере, в данных
колеса, которые получил клиент, и в чате клиента; везде проверяется, что в чате нет непереведённых ключей.

| Шаг | Что проверяется |
|---|---|
| Дерево команд и тексты | клиент получил `/adaptation info <адаптация>`, `learn` и `forget`; у клиента есть все тексты команд и строка изменений 4.31.0 |
| Подсказки | клиент спрашивает сервер, как при наборе в чате: на «zom» приходит `mob:minecraft:zombie` с названием «Зомби»; на пустое слово — не больше 200, и своя адаптация игрока с ключом, который сортируется последним, среди них |
| `learn @s 3 zombie` | на сервере этап III, у клиента колесо повернулось и показывает III, в чате сообщение об этапе и итог |
| `disable zombie` | выключено и на сервере, и в данных меню J у клиента |
| `list` | заголовок, строки, выключенная помечена: «Зомби — этап 3/4 · выключена» |
| `info dry_riptide` | заголовок, этап и подсказка бытовой адаптации |
| `enable zombie` | снова включено у клиента |
| неизвестное имя | «Нет такой адаптации: no_such_adaptation_431», этап не изменился |
| `forget @s zombie` | адаптации нет ни на сервере, ни в колесе клиента |

Jar из обычной сборки 4.31.0 (до упаковки):

| Группа | Что в папке mods | Каталог | Итог |
|---|---|---|---|
| `cmd431` | колесо и пробный мод | 192 | PASS, 9 из 9 шагов |
| `cmd431-optifine` | + OptiFine 1.20.1_HD_U_I6_pre6 | 192 | PASS, 9 из 9 |
| `cmd431-pasha-optifine` | + полный набор Паши: 87 jar (85 модов, OptiFine, tl_skin_cape) | 1113 | PASS, 9 из 9 |

С полным набором подсказок на пустое слово ровно 200 из 1113, и своя адаптация игрока среди них — так проверен
предел, который мир GameTest не достигает. Строк ERROR от колеса нет. Ошибки в логе полного набора те же, что в
прогоне 4.30.0 с тем же набором: 115 строк ERROR и 478 строк с `Exception`, построчно одинаковые (кроме адресов
объектов).

Первая попытка пробного мода упала на шаге подсказок, и причина была в самой проверке. Клиент держит только один
ожидающий запрос подсказок к серверу и отменяет прежний, а пробный мод отправил два сразу. Теперь запросы идут по
очереди, как при наборе в чате.

Релизный `adaptation-wheel-1.20.1-4.31.0-trained.jar` (`6bb65529…`) прошёл те же три группы: `cmd431`,
`cmd431-optifine`, `cmd431-pasha-optifine` — PASS, 9 из 9 в каждой, строк ERROR от колеса нет, подсказок с полным
набором снова 200 из 1113. В логе полного набора на этот раз две строки OpenGL `GL_INVALID_OPERATION` вместо одной.
Это не новая ошибка: она приходит из потока драйвера, пока OptiFine загружает связанные текстуры, в стеке нет ни
колеса, ни Boost, и по одной-две такие строки есть во всех прогонах полного набора с OptiFine начиная с 4.21.1.

## Ревью

Состязательное ревью: четыре независимых проверяющих (что делает каждая команда и разбор имён; права и
подсказки; этап командой против этапа, пройденного по таймеру; тексты) нашли 12 замечаний. Семь самых серьёзных
проверены отдельно, и все семь не подтвердились:

| Замечание | Почему не ошибка |
|---|---|
| У босса, выученного командой, в `list`/`info` этап «4/4», а не «4/5» | так считает само колесо: пятый этап появляется у записи после первого настоящего удара босса, меню J до этого тоже показывает 4/4 |
| `/adaptation reset` без подтверждения можно вызвать кликом по табличке или книге | обычный игрок не может сделать табличку или книгу с командой: это только через NBT, то есть у оператора; и `reset` без игроков сбрасывает только себя, как и раньше |
| Подсказки каждый раз пересобирают весь каталог | это доли миллисекунды на нажатие клавиши; так же каталог собирается для меню J |
| В `list <игрок>` клик подставляет `info`, который показывает этап оператора | строка `info` так и подписана: «Твой этап»; этап игрока уже виден в строке списка |
| Ключ ищется с учётом регистра, а подсказки без | как в ванили: `/give @s Minecraft:Stone` тоже подсказывается, но не выполняется |
| `husk`, `drowned`, `freeze`, `starve` не находятся | это не отдельные адаптации: удар кадавра учится как зомби, мороз — как холод, и подсказки предлагают именно их |
| `forget` оставляет память анализатора об этом уроне | память описывает сам урон, а не прогресс: забытая адаптация начинается с нуля, а анализ урона остаётся, как задумано |

Пять мелких замечаний остались без отдельной проверки. Я разобрала их сама, три исправлены:

| Что было | Исправление |
|---|---|
| `info` ничего не говорил про холод и темноту | холод показывает защиту по этапам, темнота — свет по этапам (5, 10, 15, 15 из 15) и ночное зрение на IV |
| для Бесконечности `info` писал про укорочение эффекта | свой текст Бесконечности из меню J |
| `on`, `off`, `reset` на `@a` присылали оператору (и другим операторам) по строке на каждого игрока | одна строка с числом игроков, как у `learn` и `forget`; каждый игрок по-прежнему видит своё сообщение |

Два оставлены как есть: выключенные командой записи ограничены размером каталога, а память анализатора уже
разобрана выше (это замечание пришло дважды).

Эти правки прошли второе ревью тем же способом: два проверяющих (логика и тексты с тестами), каждое
замечание — отдельной перепроверкой. Все 10 замечаний не подтвердились. Например, оператор, который сам среди
целей, видит и своё сообщение, и строку для операторов — так же ведёт себя ванильный `/gamemode`. Два замечания
верно указали на мягкие места тестов, и тесты укреплены: свет темноты проверяется на всех четырёх этапах, а у
сводной строки проверяется число игроков.

## Честные границы

- Этап V командой не выдаётся: он появляется только у босса и только после настоящих ударов.
- `learn` не лечит, даже если в настройках включено лечение после пройденного этапа (`healAfterStage`).
- Ключ ищется с учётом регистра, как ванильные ключи.
- Предел подсказок 200 не достигается в мире GameTest, поэтому то, что свои адаптации в него попадают, проверено
  только в игре с полным набором.
- Не проверено: выделенный сервер и собственные миры Паши; команды проверены в свежем мире.
